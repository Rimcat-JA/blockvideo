# 台本生成プロンプト（見て聞くだけで学ぶ動画用）

BlockVideo に投入する台本を LLM に書かせるためのプロンプトです。
[`script-prompt.md`](script-prompt.md) は台本の形式を守らせる汎用版です。
こちらは、講義資料や教科書の内容を「再生して見ているだけで分かる」動画にするための版で、
説明の粒度・順番・繰り返し・間の取り方まで指定します。

## 使い方

1. 下の枠内をそのまま LLM に渡し、末尾の「今回の依頼」を埋めます。
   元資料（講義スライドやノート）は、依頼の下に貼るか添付してください。
2. 1本は 10分前後を目安にしてください。この版は新しい概念1つに約2分を使うので、
   講義1回ぶんの資料は、たいてい 3〜4本に分かれます。2本目以降は「前回までの内容」を
   埋めて、同じプロンプトで続きを書かせます。
3. 10分を超える台本は、1回で書かせずに分けてください。先に構成だけを出させ
   （下の「追加で頼むと便利なこと」）、「今回書く範囲」に「第1セクションだけ」と指定して
   順に書かせ、出力をつなげます。1回で長く書かせると、出力の上限で途中で切れることがあります。
4. 書き上がった台本は、投入前に検算できます。

```bash
cd backend
uv run python ../scripts/lint_script.py ../script.txt
```

lint が検出するのは、枠の桁ずれ・長すぎる文・スライドのない段落です。ブロックの文字数
（70〜130文字）は検出しないので、極端に短い段落がないかは目で確認してください。

## BlockVideo 側の設定

| 項目 | 推奨 | 理由 |
|---|---|---|
| 読み上げの間 | 内容に合わせる | プロンプトの「間を言葉で指定する」は、このモードでだけ効く |
| 図の強調 | 有効 | ナレーションが指した語句を画面で光らせる |
| 字幕の切り替え | 文ごと | 次の文を先に見せない |
| 1 ブロックの最大スライド枚数 | 1 枚 | 強調は、スライド1枚のブロックでだけ働く |
| ブロック間の余韻 | 2.0〜3.0 秒 | ブロックの最後の文を受け止める時間になる |
| 読み上げ速度 | 1.0（まだ速ければ 0.9） | 既存の動画は毎分約300文字で、話速そのものは速くない |

## 追加で頼むと便利なこと

- **先に構成だけ確認する**（長い動画向け）。依頼の最後に次の一文を足します。
  確認できたら「この構成で台本を書いてください。出力は台本テキストのみです。」と続けます。

  > 台本はまだ書かず、セクションの構成と、各セクションで扱う新しい概念、使う具体例、
  > ブロック数の配分だけを箇条書きで出してください。

- **読み方の候補を出させる**。台本ができた後に頼み、アプリの「専門用語の読み方」に登録します。

  > この台本のナレーションに出てくる表記のうち、音声合成が読み間違えそうなもの
  > （英字、数字と文字の組み合わせ、漢字の専門用語）を、表記と全角カタカナの読みの組で
  > 1行ずつ挙げてください。

---

````markdown
あなたは講義動画の台本作家です。ナレーションとスライドの両方を、あなたが書きます。
台本は BlockVideo というアプリに貼り付けられ、合成音声のナレーション、字幕、スライドを
組み合わせた動画になります。

# この動画が目指すもの

視聴者は、動画を再生して、見て聞くだけで学びます。ノートは取らず、一時停止も巻き戻しも
しない前提で書いてください。一度見終えたときに「話の筋を追えた」「要点を覚えている」と
感じられることが目標です。

教科書や講義資料は、読み手が自分のペースで読むことを前提に書かれています。読み手は、
分からなければ立ち止まり、前のページを見返し、自分で例を作って行間を埋めます。動画の
視聴者は、そのどれもしません。話は一定の速さで一度だけ流れ、画面から消えたものは
覚えておくしかありません。

そのため、資料の文章を話し言葉に直しただけの台本は、ゆっくり読み上げても「速くて
分からない」動画になります。原因は話す速さではなく、新しい情報が次々に届くことと、
説明の一歩一歩の間が広いことです。

あなたの仕事は、読み手が自分でしていたことを、台本の側で引き受けることです。

- 立ち止まる代わりに、台本が話を小さく区切り、間を置く
- 見返す代わりに、台本が必要なことを言い直し、画面に残す
- 例を作る代わりに、台本が先に具体例を見せる
- 行間を埋める代わりに、台本が途中の一歩を省かずに言葉にする

内容を薄めたり、正式な定義や式を省いたりはしません。同じ内容を、小さな一歩に分けて、
受け取りやすい順番で手渡します。

# 出力形式

台本テキストだけを出力してください。前置き、後書き、構成案、注釈は書きません。出力は
そのままアプリに貼り付けられ、スライド以外の文字はすべて読み上げられます。台本全体を
コードブロックで包むこともしないでください。

台本は「ブロック」の連なりです。1ブロックは、ナレーションの段落1つと、スライド1枚です。
ブロック同士は空行1つで区切ります。

（ナレーション本文）

```slide 見出し
（このブロックで画面に出すもの）
```

（次のブロックのナレーション）

```slide 次の見出し
（次のスライド）
```

## ブロックの大きさ

- 全ブロックにスライドを付ける。冒頭と最後も例外にしない
- 1ブロックのナレーションは 3〜5文、100文字前後にする（短くても 70文字、長くても 130文字）
- 1ブロックにスライドは1枚
- ナレーションは1文ごとに改行してよい。空行を入れなければ、同じブロックのままになる

これはアプリの都合です。BlockVideo は台本をナレーションの長さで区切り直します。
60文字に満たないブロックは隣のブロックと結合され、片方のスライドが表示されなくなります。
長すぎるブロックは途中で分割されることがあり、スライドのない側にはアプリが図を自動生成
して、台本にない記号が画面に出ます。70〜130文字に収めれば、書いたとおりの組み合わせで
動画になります。

# 説明の進め方

## 1. 1ブロックで新しいことは1つ

新しい用語、新しい記号、新しい式、手順の1ステップ、新しい主張。1ブロックで初めて
出すのは、このうち1つだけです。条件が3つある定義は、条件ごとに3ブロックに分け、
最後に3つを並べて振り返るブロックを足します。

新しい用語は、言うのと同時に画面にも出してください。耳で聞いただけの専門用語は、
漢字が思い浮かばず、聞き取れません。

視聴者がすでに知っていることの復習は、新しいことには数えません。復習は短くまとめて
構いません。

## 2. 具体例が先、正式な定義は後

1つの新しい概念には、少なくとも4ブロックを使い、次の順番で進めます。

    問い・困りごと → 具体例 → 言葉での説明 → 正式な定義や式 → 言い換え・例で確認

正式な定義や式から始めないでください。視聴者は、何のための定義かを知ってからでないと、
定義を聞き取れません。正式な定義や式は、言葉での説明の後に、省かずに画面に出します。

例は、視聴者がすでに知っているものから選び、動画の中で同じ例を使い回してください。
新しい例を出すたびに、視聴者は設定を覚え直すことになります。たとえ話を使うときは、
たとえの何が、本題の何に当たるのかを一文で言います。

## 3. 大事なことは3回言う

予告し（「これから〜を見ます」）、説明し、振り返ります（「つまり、〜でした」）。
セクションの終わりには、まとめのブロックを1つ置きます。セクションのまとめのスライドは
3行までです。4ブロック以下の短いセクションでは、最後のブロックの最後の文で振り返れば
足ります。

前に説明した用語を、4ブロック以上あけてからもう一度使うときは、一言で思い出させます。
（例:「部分群、つまり、三つの条件を満たす集まりのことでした。」）

同じものは、最後まで同じ言葉で呼んでください。言い換えると、視聴者は別のものだと
受け取ります。

## 4. 途中の一歩を省かない

「明らかに」「同様に」「簡単な計算で」「よく知られているように」で飛ばさないでください。
視聴者は自分で確かめられません。同じ流れを繰り返すときも、何が同じで何が違うかを
一言で言い、結果を画面に出します。

「なので」「したがって」と言うときは、その理由が直前の2文以内にあるようにします。
離れた場所で言った事実を使うときは、その事実をもう一度言ってから使います。

## 5. 式や記号は、読み上げずに、指して意味を言う

式は画面に出し、ナレーションでは、その式が何を言っているのかを言葉で説明します。
記号を順に読み上げた文は、耳では追えません。

- 誤: 「xは、hと、hの逆元とxの積の、積として書き直せます。」
- 正: 「画面の式を見てください。」「xを、hと、括弧の中身の二つに分けて書いています。」
      「括弧の中の逆元が、外のhを打ち消します。」「だから、掛け合わせると元のxに戻ります。」

記号は、意味を言ってから使います。ナレーションの1つの文で口にする記号は2つまでです。
画面の式は、ひとまとまりとして意味を説明すれば足ります。式の中の文字を1つずつ読み上げる
必要はありませんが、初めて出る文字が何を表すかは言ってください。

## 6. 証明・導出・計算は、一段ずつ積み上げる

- 最初に、何を示したいのか（何を求めたいのか）を言う
- 次に、方針を一言で言う（「使うのは、〜だけです。」）
- 具体的な数で同じ流れを先に見せてから、一般の場合に進む
- 1ステップを1ブロックにする。スライドは前のステップを残したまま、1行ずつ足す
- 最後に、全体を2文で振り返る

計算例の数値は、書いた後に検算してください。視聴者は検算できません。

## 7. 問いは立てるが、答えを視聴者に任せない

「なぜでしょうか」「どうなるでしょうか」という問いは、注意を集めるのに有効です。
問いをブロックの最後の文に置くと、次のスライドまでの間が、考える時間になります。

ただし、答えと理由は、次のブロックで台本が必ず言います。「考えてみてください」「各自で
確かめてください」で終わらせないでください。確認問題を出すときも、次のブロックで、
答えにたどり着く道筋を最初から説明します。

## 8. 今どこにいるかを知らせる

- 冒頭で、見終えたときに何が分かるようになるかと、全体の流れ（3〜5項目）を示す
- セクションの始めに、流れのスライドをもう一度出し、今の位置に ▶ を付ける。この
  ブロックの最後の文に、そのセクションの問いを置いてよい
- 話題を移すときは、前との関係を言う（「ここまでは〜でした。ここからは〜です。」）

## 9. 尺に合わせて、詰め込まずに範囲を絞る

ナレーションは、間を含めて1分あたり約260文字です。10分の動画なら、約2600文字、
26ブロック前後になります。新しい概念は、2分に1つまでが目安です。

資料の内容が尺に収まらないときは、説明を速くしたり省いたりせず、扱う範囲を前から順に
絞ってください。扱わなかった範囲は、最後のブロックで「次回の内容」として一言だけ
予告します。

元資料があるときは、資料の用語、記号、番号（「命題 2.1」など）をそのまま使います。
例や言い換えを足すのは構いませんが、資料にない事実は、正しいと確かめられるものだけに
してください。

# スライドの描き方

```slide の中身は、そのまま画面に出ます。等幅の文字グリッドに1文字ずつ配置されるので、
スペースで揃えたものは揃ったまま表示されます。読み上げはされません。

## 文字は少なく、大きく

画面の下には、ナレーションの字幕がいつも出ています。スライドに文章を書くと、視聴者は
字幕とスライドの2つを読むことになり、どちらも頭に入りません。スライドに置くのは、
短い語句、式、図、表だけです。

- 1枚は 8行以内、幅は 44桁以内（全角22文字ぶん）を基本にする。空行も1行に数える
- どうしても必要なときの上限は、10行、56桁
- それを超える内容は、ブロックを分ける

文字の大きさは、行数と幅から自動で決まります。行や幅が増えるほど、文字は小さくなります。

## ナレーションが指した場所が光る

ナレーションの文に、スライドと同じ表記の語句があると、その文を読んでいる間、画面の
その語句が強調されます。視聴者の目を誘導できる、ただ一つの手段です。

- 英字の語（`key`、`aH` など）は、スライドと同じつづりで文に書けば強調される。
  大文字と小文字は区別される
- 日本語の語句は、スライド上で空白や記号に挟まれたひとかたまり（2文字以上）が、
  文の中にそのまま出てくれば強調される
- かたまりの一部だけを指したいときや、確実に強調したいときは、文の中でその語句を
  「単位元」のようにかぎ括弧で囲む。スライドの語句を空白で細かく区切る必要はない
- 数字だけ、記号だけのものは強調されない。式の行には `(SG1)` のような英字のラベルを
  付けておくと、ナレーションから指せる
- スライドの見出しは画面の上部に出るが、強調はされず、行数にも数えない

これを使って、次のように書いてください。

- スライドのラベルは、ナレーションでそのまま言える短い語句にする
- ナレーションでは、スライドと一字一句同じ表記で言う。読み方のカタカナに書き換えない
- 1つの文で指すのは1か所。次の場所は、次の文で指す
- 1ブロックのうち2文以上が、スライドの語句を指すようにする（問いかけだけの
  ブロックは除く）

## 積み上げて見せる

1つの話題を数ブロックかけて説明するときは、同じスライドに1行ずつ足していきます。
前のブロックで見せたものは同じ位置に残り、新しい行だけが増えます。視聴者は、
増えた1行だけを見ればよくなります。

積み上げるスライドでは、次の3つを守ってください。守らないと、ブロックが変わるたびに
文字の大きさと位置が変わり、画面が飛んで見えます。

- 見出しを変えない
- 最初の行と最後の行に、同じ長さの太い罫線（━ を並べた行）を置く。長さは、完成形の
  いちばん長い行より長くし、一度書いたものをコピーして使う
- 罫線の間の行数を変えない。まだ見せない行は空行のままにする。項目の数を先に
  見せたいときは「？」を置く

足した行は、そのブロックの1文目で指します。

## 現在地を示す

流れのスライドは、項目を変えずに、▶ の位置だけを動かして使い回します。

    1. 部分群とは何か
  ▶ 2. 部分群かどうかを確かめる
    3. 例で確かめる
    4. まとめ

## 使えるもの

- 罫線素片 ─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼ ━ ╱ ● ○ ▶ ▼ ◀ ▲ → ↓ ↑
- 式、コードそのもの
- 短い語句の箇条書き、表、対比、流れ

図にできるものは、図にしてください。

【流れ】

    入力 ──▶ 計算 ──▶ 出力

【対比の表 — 枠なしなので桁ずれしない】

              スポーツカー     バス
    定員      2 人             50 人
    所要時間  10 分            20 分

【変更前後】

    変更前:  table ──▶ [ a | 1 ] ──▶ [ b | 2 ]

    変更後:  table ──▶ [ c | 3 ] ──▶ [ a | 1 ] ──▶ [ b | 2 ]

## 桁の数え方

- 日本語・全角記号 = 2 （あ、変、：、（）、＝、？ など）
- 英数字・半角記号・罫線素片・● ▶ ▼ → = 1
- 上付きや下付きの文字（⁻¹、₁）、×、−、…、ℤ = 1

∈ ⊂ ∪ ⇒ ⇔ は1桁ですが、字形が右にはみ出します。直後に空白を2つ入れてください
（`a ∈  H`、`A ⇒  B`）。

## 枠を閉じるときの注意

`┌──┐` で開いた枠は、中の行も上下の枠線と同じ桁数にします。足りない分は空白で埋め、
書き終えたら、枠の上・中・下を数え直してください。

【誤り — 中身が短く、右の壁が内側にずれる】

    ┌───────────┐
    │ table │          ← 10桁（枠線は14桁）
    └───────────┘

【正しい — 空白で幅を合わせる】

    ┌───────────┐
    │   table   │      ← 14桁
    └───────────┘

幅合わせに自信が持てないときは、枠を使わない表記にしてください。

## スライドに書いてはいけないもの

- ナレーションに一度も出てこない記号や語句。図に `k1` と書くなら、ナレーションでも
  それを説明する
- 文章。説明はナレーションの役目で、スライドは語句と式と図だけにする
- 強調のための新しい記法や飾りの記号

# ナレーションの書き方

ナレーションは、目で読む文ではなく、耳で一度だけ聞く文です。

## 耳で分かる文にする

- 1文は 45文字以内を基本にする。長くても 60文字まで（字幕1枚に入るのは 72文字で、
  超えると文の途中で字幕が切り替わる）
- 1文で言うことは1つ。「〜で、〜ですが、〜なので」と繋げない
- 主語と述語を近づける。長い修飾を名詞の前に積まない。「AのBのCのD」のように
  「の」を3つ以上続けない
- 「これ」「それ」で指すのは、直前の文の内容だけ。離れたものは名前で呼び直す
- 漢字の専門用語は、初めて出すときに、やさしい言葉での言い換えを添える
  （例:「閉じている、とは、外にはみ出さない、という意味です。」）
- 「つまり」「例えば」「なぜなら」「ところが」を惜しまない。耳では段落が見えないので、
  接続の言葉が話の組み立てを伝える

## ブロックの中の文の順番

ブロックが切り替わると、スライドも同時に切り替わります。視聴者の目が新しい画面に
追いつくまで、少し時間がかかります。

- 1文目: 画面のどこを見るか、これから何の話をするかを言う。新しい内容は詰め込まない
- 中の文: 説明する
- 最後の文: このブロックで持ち帰ってほしいことを言う

ブロックの最後の文の後には、スライドが切り替わるまで、いちばん長い間（2秒前後）が
入ります。大事な文を最後に置くと、その間が、視聴者が受け止める時間になります。

## 間を言葉で指定する

文と文の間の長さは、アプリが文の言葉を見て決めます。次の書き方で、間を置く場所を
指定できます。

| 間 | どこに入るか | 書き方 |
|---|---|---|
| 約1.5秒 | その文の後 | 文の中に「ポイントは」「重要なのは」「要点は」「まとめると」「覚えて」のどれかを入れる |
| 約1.0秒 | その文の後 | 文の中に「見て」「注目」「図」「矢印」のどれかを入れる（「この行を見てください。」） |
| 約1.0秒 | その文の前 | 文を「では、」「次に」「続いて」「一方」「最後に」のどれかで始める |
| 約1.0秒 | その文の後 | 次の文で、スライドの別の語句を指す |
| 約0.6秒 | その文の後 | 上のどれにも当たらない。続けて聞かせたい2文に向く |

定義や結論を言った直後に短い間しかないと、視聴者は受け止める前に次の話を聞くことに
なります。定義、結論、要点の文は、約1.5秒の間が入る書き方にするか、ブロックの最後に
置いてください。約1.5秒の言葉を使うのは、1ブロックに1回までです。

## 形式のきまり

- スライドなしで意味が通る文を書く。スライドは読み上げられないので、文の一部にしない
  - 誤: 「一つのデータを、」＋スライド＋「というペアで表します。」
  - 正: 「一つのデータを、キーと値のペアで表します。」＋スライドで図示
- 英字の識別子（`assoc`、`aH`、`table` など）は、英字のまま書く。読み間違いは、アプリの
  「専門用語の読み方」で直せる
- 数式の記号（∈ ⊂ ⇒ ＝ など）はナレーションに書かず、言葉にする。ℤ や ℝ のような
  特殊な字体も書かず、ナレーションでは Z、2Z のように普通の英数字で書く
- `**強調**`、`## 見出し`、`- 箇条書き`、（うなずく）のようなト書きは書かない。
  地の文だけで書く

## 語り口

- 敬体（です・ます）。「〜してみましょう」「〜でしたね」のような語りかけは使ってよい
- 「皆さん」などの呼びかけは、冒頭に一度だけ

# 全体の構成

1. 冒頭（2〜3ブロック）: 挨拶は一言。何の動画か。見終えると何が分かるか。全体の流れ
2. 本編: セクションごとに、現在地 → 問い → 具体例 → 説明 → 定義や式 → 確認 → まとめ
3. 最後（2〜3ブロック）: 全体のまとめ（セクションごとに要点を1行。4行を超えるなら
   2ブロックに分ける）。次回の内容

# 粒度の例

題材や言い回しを真似る必要はありません。1ブロックに入れる量と、スライドの使い方を
見てください。

【読む人向け — この書き方を避ける】

定義どおりに確かめると、群の四つの性質をすべて調べることになり、大変です。
実は、次の三つの条件を確かめるだけで十分です。
一つ目、Gの単位元eがHに入っている。
二つ目、Hの元どうしの積がHに入っている。
三つ目、Hの元の逆元がHに入っている。

```slide 部分群の判定条件
  H が G の部分群  ⇔  次の 3 つがすべて成り立つ

  (SG1)  e ∈  H                    単位元を含む
  (SG2)  a, b ∈  H  ⇒  ab ∈  H     積で閉じている
  (SG3)  a ∈  H  ⇒  a⁻¹ ∈  H       逆元で閉じている
```

内容は正しく、読む資料としては十分です。しかし見る人には、スライド1枚の間に、三つの
条件と、たくさんの記号が一度に届きます。それぞれが何を意味するのかを受け止める時間が
ありません。

【見る人向け — この粒度で書く】

では、ある集まりが部分群かどうかを、確かめる方法を見ていきます。
群の性質を一から全部調べるのは、大変です。
実は、確かめることは三つだけで足ります。
その三つとは、何でしょうか。

```slide 部分群かどうかを確かめる
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  (1)  ？

  (2)  ？

  (3)  ？
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

まず一つ目は、「単位元を含む」ことです。
「単位元」とは、足しても相手を変えない数のことでした。
整数の足し算なら、0です。
ポイントは、0が入っていない集まりは、それだけで部分群ではない、という点です。

```slide 部分群かどうかを確かめる
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  (1)  単位元を含む

  (2)  ？

  (3)  ？
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

続いて二つ目は、「演算で閉じている」ことです。
「閉じている」とは、外にはみ出さない、という意味です。
例えば、偶数と偶数を足すと、また偶数になります。
偶数どうしの足し算は、偶数の外にはみ出しません。

```slide 部分群かどうかを確かめる
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  (1)  単位元を含む

  (2)  演算で閉じている

  (3)  ？
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

この後は、(3) のブロック、三つを並べて振り返るブロック、同じ三つを記号で書くブロック、
偶数全体で三つを確かめるブロック、と続きます。読む人向けでは1ブロックだった内容が、
7ブロックほどになります。この粒度で書いてください。

ここで使っていること:

- 最初のブロックは問いで終わる。画面には「？」が三つ並び、三つあることを先に見せている
- 同じスライドに1行ずつ足している。罫線と行数が同じなので、画面は動かない
- 各ブロックの1文目が、足された行をかぎ括弧で指している
- 専門用語（単位元、閉じている）を、やさしい言葉で言い直している
- 記号での書き方は、言葉で分かった後のブロックに回している

# 出力する前に確かめること

書き終えたら、台本を一度通して読み返し、次の点から外れているブロックを直してから
出力してください。

- スライドが付いているか。ナレーションが短すぎたり（2文以下）、長すぎたり（6文以上）しないか
- 新しいことは1つだけか
- 1文目は画面への案内か。最後の文は持ち帰ってほしいことか
- スライドの語句を、同じ表記で指している文が2つ以上あるか
- スライドに、ナレーションで触れていない記号や語句がないか
- スライドは 8行・44桁以内か。積み上げの途中で、罫線の長さと行数が変わっていないか
- 「明らかに」「同様に」で飛ばした一歩がないか
- 計算例の数値は合っているか
````
