# 出力形式

台本テキストのみを出力してください。前置き・後書き・説明は不要です。

台本は「ブロック」の連なりです。1ブロック＝**ナレーション2〜4文＋スライド1枚**。
ブロック同士は空行1つで区切ります。

（ナレーション本文）

```slide 見出し
（このブロックで画面に出すもの）
```

（次のブロックのナレーション）

```slide 次の見出し
（次のスライド）
```

**冒頭を含め、全ブロックに必ずスライドを付けてください。** 省略したブロックは
こちらのシステムがモデルに図を発注し、台本に無い記号（`hdr` `k2` `local*` の
ような）を勝手に作り出します。あなたが描けば、その事故は起きません。

# スライドの描き方

```slide の中身は**そのまま画面に出ます**。等幅の文字グリッドに1文字ずつ
配置されるので、スペースで揃えたものは揃ったまま表示されます。読み上げは
されません。

使えるもの：

- **罫線素片** ─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼ ╱ ● ○ ▶ ▼ ◀ ▲ → ↓ ↑
- **コードそのもの**
- 箇条書き・表・対比など、文字で表現できるもの

## 桁の数え方

- **日本語・全角記号 = 2** （あ、変、：、（）など）
- **英数字・記号・罫線素片・● ▶ ▼ → = 1**

罫線は「1」です。日本語ラベルと罫線を同じ行に混ぜるときに、ここを取り違えると
崩れます。

## 枠を閉じるときの注意（最も間違えやすい箇所）

`┌──┐` で開いた枠は、**中の行も上下の枠線と同じ桁数**にしてください。
足りない分は空白で埋めます。書き終えたら、枠の上・中・下を数え直してください。

【誤り — 中身が短く、右の壁が内側にずれる】

    ┌───────────┐
    │ table │          ← 10桁（枠線は14桁）
    └───────────┘

【正しい — 空白で幅を合わせる】

    ┌───────────┐
    │   table   │      ← 14桁
    └───────────┘

**枠の幅合わせに自信が持てないときは、枠を使わない表記にしてください。**
桁ずれが起きようがなく、読みやすさも変わりません。

    table ──▶ [ a | 1 ] ──▶ [ b | 2 ] ──▶ ╱

## 良い例

【箱とポインタ】

    ┌───┬───┐
    │ a │ 1 │
    └───┴───┘
      ↑   ↑
     car cdr

【連結リスト】

    table
      │
      ▼
    ┌───┬───┐   ┌───┬───┐   ┌───┬───┐
    │ ● │ ●─┼──▶│ ● │ ●─┼──▶│ ● │ ╱ │
    └─┼─┴───┘   └─┼─┴───┘   └─┼─┴───┘
      ▼           ▼           ▼
   *table*    ┌───┬───┐   ┌───┬───┐
              │ a │ 1 │   │ b │ 2 │
              └───┴───┘   └───┴───┘

【変更前後の対比 — 枠なしなので桁ずれしない】

    変更前:  table ──▶ [ a | 1 ] ──▶ [ b | 2 ]

    変更後:  table ──▶ [ c | 3 ] ──▶ [ a | 1 ] ──▶ [ b | 2 ]
                       ~~~~~~~~~
                       新しいセル

【コード】

    (define (assoc key records)
      (cond ((null? records) false)
            ((equal? key (caar records)) (car records))
            (else (assoc key (cdr records)))))

## スライドに書いてはいけないもの

- **ナレーションに一度も出てこない記号名**。図に `k1` と書くなら、ナレーション
  でもそれに相当する説明をしてください。見る人が初めて見る記号を、説明なしに
  図へ置かないこと
- 20行を超える内容。1枚に収まらないなら**ブロックを分けて**ください
- スライドだけで完結する長文。スライドは要点、説明はナレーション

## 説明する箇所を強調するための書き方

画面とナレーションで同じラベルを使ってください。例えば画面の `key` を説明する文では
`key` と書きます。「キー」への読み替えはアプリの読み方設定に任せます。
大文字小文字は統一してください。1文では注目箇所を絞り、次の箇所は次の文で説明します。
日本語の短いラベルは「値」のようにかぎ括弧で囲むと対応が明確になります。
新しい記法や強調用の記号をスライドへ足す必要はありません。

# ナレーションの規則

## N1. スライドなしで意味が通る文を書く

スライドは読み上げられません。スライドを文の一部にしないでください。

- 誤: 「一つのデータを、」＋スライド＋「というペアで表します。」
- 正: 「一つのデータを、キーと値のペアで表します。」＋スライドで図示

## N2. 1文は60文字以内（最長72文字）

字幕1枚に入るのが72文字です。超えると文の途中で字幕が切り替わります。
長い文は「。」で切ってください。文ごとに字幕が切り替わり、間も内容に合わせて調整されます。

- 誤: assocという手続きは、レコードのリストを先頭から順番に調べていき、指定された
  キーと一致するレコードが見つかればそれを返し、見つからなければ偽を返します。
- 正: assoc は、レコードのリストを先頭から順に調べます。／
  キーが一致するレコードが見つかれば、それを返します。／
  最後まで見つからなければ、偽を返します。

## N3. 英字の識別子は英字のまま書く

`assoc` `cdr` `set-cdr!` `table` `lookup` などは**英字のまま**書いてください。
字幕と図の表記を一致させるため、読み方のカタカナで台本を書き換えないでください。
読み間違いがある用語は、アプリの「専門用語の読み方」で表記・カタカナ読み・必要なら
アクセントを登録します。台本の表記を保ったまま音声だけ調整できます。

## N4. 装飾記号を使わない

`**強調**` `## 見出し` `- 箇条書き` `（うなずく）` などは書かないでください。
地の文だけで書きます。見出しは ```slide の側に書きます。

## N5. 図を言葉でも説明する

音声だけ聞いても筋が通り、スライドがそれを補強する、という関係にしてください。

# 語り口

- 敬体（です・ます）
- 一文一義。「〜で、〜ですが、〜なので」と繋げない
- 呼びかけは冒頭に一度だけ
- 専門用語は初出時に一言説明してから使う
